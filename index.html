A Stripe-shaped .NET client
for eGovPay

A community-built C# SDK for the Philippine government payment gateway — one client, resource-scoped services, typed models, retries, and webhook verification. The OAuth layer is real. The payment endpoints are educated guesses until eGovPay's docs are public.

Quickstart

Direct PaymentIntent control, or hand the whole UI to eGovPay with a hosted checkout session.

using EGovPay;
using EGovPay.Models.Payments;

var client = new EGovPayClient(new EGovPayClientOptions
{
    PartnerCode = "YOUR_PARTNER_CODE",
    PartnerSecret = "YOUR_PARTNER_SECRET",
    Environment = EGovPayEnvironment.Sandbox,
});

var intent = await client.PaymentIntents.CreateAsync(new PaymentIntentCreateOptions
{
    Amount = 150000, // PHP 1,500.00, in centavos
    Description = "Business Permit Renewal - BR-2026-00123",
    ReferenceNumber = "BR-2026-00123",
    AllowedPaymentChannels = new() { PaymentChannel.GCash, PaymentChannel.Card },
});

var confirmed = await client.PaymentIntents.ConfirmAsync(intent.Id, new PaymentIntentConfirmOptions
{
    PaymentChannel = PaymentChannel.GCash,
});

Console.WriteLine($"Send the payer to: {confirmed.CheckoutUrl}");
var session = await client.CheckoutSessions.CreateAsync(new CheckoutSessionCreateOptions
{
    Amount = 150000,
    SuccessUrl = "https://your-agency-portal.gov.ph/payments/success",
    CancelUrl = "https://your-agency-portal.gov.ph/payments/cancel",
});

Console.WriteLine(session.Url); // redirect the payer here

Built-in plumbing

The parts of this SDK that don't depend on eGovPay's undocumented schema.

🔁

Retries & idempotency

Mutating requests get a stable Idempotency-Key reused across retries. Transient failures back off exponentially, up to MaxNetworkRetries.

🧯

Typed errors

EGovPayApiException for non-2xx responses, EGovPayAuthenticationException for OAuth failures — both carry the raw response.

🔐

Real OAuth

Partner-code/secret exchange against the shared eGov API OAuth host — the one part of this SDK verified against public docs.

🧩

Stripe-familiar shape

Resource services, options objects, and a single entry-point client — if you've used Stripe.net, this will feel familiar immediately.

How it's laid out

EGovPayClient.cs Entry point; owns the HttpClient + token cache EGovPayClientOptions.cs Configuration (credentials, environment, retries, webhook secret) Auth/ OAuth token exchange + caching against oauth.e.gov.ph Http/ Transport layer: retries, idempotency keys, error mapping Models/ Request/response POCOs, grouped by resource Services/ One class per resource (PaymentIntents, CheckoutSessions, Refunds, ...) Exceptions/ EGovPayException hierarchy Utils/ EGovPayEndpoints (the placeholder registry), query-string helpers Examples/ Runnable console sample

Webhooks

Mirrors Stripe.net's EventUtility.ConstructEvent. The signing scheme itself is unconfirmed — treat this as a starting point.

var evt = client.ConstructWebhookEvent(rawRequestBody, request.Headers["EGovPay-Signature"]);
if (evt.Type == "payment_intent.succeeded")
{
    var intent = evt.Data.GetObject<PaymentIntent>();
    // ...
}
